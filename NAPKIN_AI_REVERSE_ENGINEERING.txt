SECTION 3: SEMANTIC EXTRACTION — HOW THE AI UNDERSTANDS TEXT
================================================================================

Before Napkin AI can draw anything, it must UNDERSTAND the text.
This is called "Semantic Graph Extraction" and involves:

  1. ENTITY EXTRACTION (NER — Named Entity Recognition)
     - Identify the KEY CONCEPTS in the text
     - Example: "Photosynthesis", "Chlorophyll", "CO2", "Glucose"

  2. RELATIONSHIP EXTRACTION (SVO — Subject-Verb-Object Triplets)
     - Identify HOW concepts connect
     - Example: "Chlorophyll" → CAPTURES → "Sunlight"
     - Example: "Plants" → CONVERT → "CO2 into Glucose"

  3. HIERARCHY DETECTION
     - Identify which concepts are parent/child
     - Example: "Photosynthesis" is the PARENT of
       "Light Reactions" and "Dark Reactions"

  4. INTENT CLASSIFICATION (The Router)
     - Is this text a PROCESS (→ use flowchart)?
     - Is this text a COMPARISON (→ use table/matrix)?
     - Is this text a HIERARCHY (→ use mind map)?
     - Is this text a TIMELINE (→ use timeline)?

WHAT WE CAN LEARN:
  → Our current prompt just says "chunk into blocks."
  → We need to add RELATIONSHIP EXTRACTION to our JSON schema:
    {
      "title": "...",
      "blocks": [...],
      "connections": [
        { "from": "block_id_1", "to": "block_id_2", "label": "leads to" }
      ],
      "layout_hint": "flowchart" | "mind_map" | "grid" | "timeline"
    }
  → This allows us to draw ARROWS between sticky notes automatically!
  → The "layout_hint" lets us pick different layout algorithms.

SECTION 4: LAYOUT ALGORITHMS — THE MATH THAT MAKES IT BEAUTIFUL
================================================================================

This is Napkin AI's SECRET WEAPON. The AI does NOT decide where to put boxes.
A DETERMINISTIC MATH ALGORITHM does. Here are the key algorithms:

──────────────────────────────────────────
4A. DAGRE (Directed Acyclic Graph Layout)
──────────────────────────────────────────
  WHAT: An algorithm that takes nodes + edges and calculates perfect
        X,Y positions so that flow goes top-to-bottom or left-to-right,
        and edges (arrows) never cross each other.
  
  MATH: Based on the "Sugiyama" algorithm:
    Step 1: Assign each node to a LAYER (rank) based on dependencies.
    Step 2: MINIMIZE EDGE CROSSINGS by permuting node order within layers.
    Step 3: Calculate final X,Y coordinates with uniform spacing.
  
  USE CASE: Flowcharts, process diagrams, dependency graphs.
  
  NPM PACKAGE: `dagre` or `@dagrejs/dagre`
  
  FOR STUDYOS:
    → When the AI detects a PROCESS or STEP-BY-STEP input,
      use Dagre to auto-generate a flowchart layout.

──────────────────────────────────────────
4B. D3-FORCE (Force-Directed Graph Layout)
──────────────────────────────────────────
  WHAT: A PHYSICS SIMULATION. Each node repels other nodes (like magnets
        with the same polarity). Connected nodes attract each other
        (like a spring). The simulation runs until equilibrium.
  
  THE PHYSICS:
    - Repulsion Force (Coulomb's Law):
        F = k * (q1 * q2) / r²
        Every node pushes every other node away.
    
    - Attraction Force (Hooke's Law / Spring):
        F = -k * x
        Connected nodes pull toward each other.
    
    - Collision Force:
        Prevents nodes from overlapping by treating each as a circle
        with a defined radius.
    
    - Center Gravity:
        A weak force that pulls all nodes toward the center of the
        canvas, preventing the graph from drifting off-screen.
  
  USE CASE: Mind maps, concept webs, organic relationship diagrams.
  
  NPM PACKAGE: `d3-force`
  
  FOR STUDYOS:
    → When the AI detects a MIND MAP or CONCEPT WEB input,
      use d3-force to auto-arrange blocks organically.
    → The physics simulation makes it feel ALIVE—nodes gently bounce
      and settle into place, which looks incredible on a whiteboard.

──────────────────────────────────────────
4C. ELK (Eclipse Layout Kernel)
──────────────────────────────────────────
  WHAT: An industrial-strength, enterprise-grade layout engine.
        Supports dozens of layout algorithms out of the box.
  
  USE CASE: Massive, complex diagrams with nested sub-graphs.
  
  NPM PACKAGE: `elkjs`
  
  FOR STUDYOS:
    → Overkill for now, but useful in the future if we support
      nested/collapsible groups of sticky notes.

──────────────────────────────────────────
4D. MASONRY / GRID LAYOUT (What We Have Now)
──────────────────────────────────────────
  WHAT: A simple 2-column grid where items are placed in the
        shortest column to balance height.
  
  MATH: Track leftY and rightY. Place each block in the column
        with the smaller Y value.
  
  FOR STUDYOS:
    → This is our CURRENT layout. It works for simple note dumps,
      but it looks boring and "webpage-like" compared to Napkin AI.
    → It should be the DEFAULT fallback, not the ONLY option.

SECTION 5: THE RENDERING ENGINE — HOW TO MAKE IT LOOK STUNNING
================================================================================

Napkin AI renders using SVG/Canvas with custom styling.
WE render using Excalidraw. Here is what we're doing wrong and how to fix it:

──────────────────────────────────────────
5A. USE EXCALIDRAW'S SKELETON API (CRITICAL FIX!)
──────────────────────────────────────────
  RIGHT NOW: We manually construct raw JSON element objects with dozens
  of properties (id, seed, version, versionNonce, etc). This is fragile
  and is WHY text was disappearing — we were missing properties that
  Excalidraw internally requires.

  THE FIX: Use Excalidraw's official `convertToExcalidrawElements` API.
  It takes a MINIMAL "skeleton" and fills in all the missing properties
  for us automatically.

  BEFORE (our current, fragile approach):
    {
      id: generateId(),
      type: "text",
      x: 100, y: 100,
      width: 200, height: 30,
      text: "Hello",
      fontSize: 20,
      fontFamily: 1,
      strokeColor: "#000",
      // ...20 more properties we might forget
    }

  AFTER (the correct approach):
    import { convertToExcalidrawElements } from "@excalidraw/excalidraw";

    const elements = convertToExcalidrawElements([
      {
        type: "rectangle",
        id: "box-1",
        x: 100, y: 100,
        width: 400, height: 200,
        backgroundColor: "#e0f2fe",
        strokeColor: "#0284c7",
        fillStyle: "solid",
        roundness: { type: 3 },
      },
      {
        type: "text",
        text: "My Heading",
        x: 120, y: 120,
        fontSize: 24,
        containerId: "box-1",  // ← BINDS text inside the rectangle!
      }
    ]);

  WHY THIS IS BETTER:
    → Excalidraw handles ALL the internal properties automatically.
    → Text wrapping is handled NATIVELY by the engine when
      containerId is set. No more manual wrapText() math!
    → Text will NEVER disappear because the engine fills in
      lineHeight, originalText, baseline, etc.

──────────────────────────────────────────
5B. BOUND TEXT (Container Binding)
──────────────────────────────────────────
  In Excalidraw, you can BIND a text element to a rectangle.
  This means:
    - The text auto-wraps to fit the rectangle's width.
    - When you resize the rectangle, the text reflows.
    - When you move the rectangle, the text moves with it.
    - The text is ALWAYS perfectly centered/padded inside.

  This is exactly how a real sticky note works!

  TO DO THIS:
    1. Create a rectangle element with a specific ID.
    2. Create a text element with `containerId: rectangle_id`.
    3. Pass both to `convertToExcalidrawElements`.
    4. Excalidraw handles the rest.

  FOR STUDYOS:
    → This would completely eliminate our manual wrapText() function.
    → This would eliminate text overflowing outside sticky notes.
    → This would make the sticky notes fully interactive and resizable.

SECTION 6: VISUAL DESIGN PRINCIPLES WE CAN STEAL
================================================================================

1. COLOR PALETTES
   Napkin AI uses carefully curated, HARMONIOUS color palettes.
   Not random colors, but palettes from color theory:
   
   → Our current palette is okay but flat.
   → We should use HSL-based palettes with consistent saturation:
     Definition:  hsl(200, 85%, 93%) background, hsl(200, 85%, 28%) text
     Concept:     hsl(270, 85%, 93%) background, hsl(270, 85%, 28%) text
     Example:     hsl(48,  95%, 78%) background, hsl(48,  95%, 25%) text
     Warning:     hsl(0,   85%, 93%) background, hsl(0,   85%, 28%) text

2. CONNECTOR ARROWS
   Napkin AI draws beautiful curved arrows between related concepts.
   → We already have an arrow generator in excalidraw-generator.ts.
   → We need the AI to output "connections" in its JSON.
   → Then the layout engine should auto-draw arrows.

3. ICONS / EMOJI BADGES
   Napkin AI uses small icons next to headings to visually categorize.
   → We can prepend emoji to headings: 📘 Definition, 💡 Concept, etc.
   → This costs nothing and massively improves scannability.

4. SHADOW & DEPTH
   Napkin AI boxes have subtle drop shadows for depth.
   → Excalidraw rectangles don't natively support shadows.
   → BUT we can fake it by placing a slightly offset, darker
     semi-transparent rectangle behind each sticky note.

5. VISUAL HIERARCHY
   → Title should be 2x larger than headings.
   → Headings should be bold, body should be regular weight.
   → Use font size differences: Title=48, Heading=24, Body=18.
